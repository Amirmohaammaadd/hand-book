۱. timeoutId چرا بیرون از تابع برگشتی است؟
چون باید بین فراخوانی‌ها باقی بماند. به این closure می‌گویند: تابع برگشتی، متغیرهای تابعی را که در آن ساخته شده به یاد دارد.

۲. اگر clearTimeout را برداریم چه می‌شود؟
debounce خراب می‌شود و به یک «تأخیر» ساده تبدیل می‌شود. اگر سه بار صدا بزنی، func سه بار اجرا می‌شود، فقط هر کدام با wait میلی‌ثانیه تأخیر.

۳. تابع برگشتی چرا function است و arrow نیست؟
چون arrow this خودش را ندارد و نمی‌تواند this کسی را که صدایش زده بگیرد.

۴. داخل setTimeout چرا arrow است؟
چون arrow this را از تابع بیرونی قرض می‌گیرد. اگر function معمولی بود، this گم می‌شد.

۵. چرا apply؟ راه دیگری هم هست؟
برای اینکه this و آرگومان‌ها به func برسند. با call یا bind هم می‌شود. جزئیاتش در پایین آمده.

۷. اگر wait = 0 باشد، func همان لحظه اجرا می‌شود؟
نه. setTimeout(..., 0) هم کار را به بعد از تمام شدن کد فعلی موکول می‌کند. این سؤال در واقع درباره event loop است.
